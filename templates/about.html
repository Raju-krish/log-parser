Built around the real pain of debugging RDKB device logs. Each card is a frustration engineers actually hit — and how Log Parser takes it away.

🧩 Scattered across dozens of files

“A single Wi-Fi drop is smeared across wifihal, wifimgr, wifimon and messages — I'm flipping between files trying to line up what happened when.”

How Log Parser solves it
  • Merges every file into one chronological timeline, color-coded per source with filename badges
  • Switch to a per-file Separate view, or hide / include any log from a clickable legend
  • Aligned monospaced columns so you scan by eye, fast

🕒 The same moment is written a different way in every file

“I know the outage hit around 11:14 on 05-05 — but I can't just grep the time. One file writes it 260505-11:14:07, another 2026-05-05T11:14:00Z, syslog only says May 5 11:14:03, and one drops the punctuation entirely: 20260505 111407. Same instant, a different string in every file — so a plain search finds none of them.”

How Log Parser solves it
  • Detects ~12 RDKB timestamp formats (even a leading [OneWifi]-style tag before the stamp) and normalizes every one to a single sortable UTC value
  • So one time-range filter spans every file at once — no grepping for a moment each log spells differently
  • Handles 2-digit boot years and year-less syslog; lines with no stamp stay anchored to the entry above them

📦 Sessions split across separate tarballs

“A device's logs arrive as a zip of separate tars — one holds 1–2 pm, the next 2–5 pm. I untar every one by hand, and even then I still can't line them up on a single timeline.”

How Log Parser solves it
  • Drop the whole zip — it auto-extracts every nested tar, no manual untarring
  • A bundle picker lets you load one, several, or all session tars at once
  • Every session is merged onto one continuous, time-sorted timeline — 1–2 pm and 2–5 pm sit end to end

🔎 grep gives you hits, not context

“I grep brlan0, get 200 matches with no surroundings, and still can't see what happened right before it failed.”

How Log Parser solves it
  • Global search jumps straight to a match, sitting in its natural place on the timeline so you see the lines of context around it
  • A floating match navigator steps through every hit (next / prev) with the word highlighted
  • Zoom in fast with a time-range filter and case-insensitive search

🚦 The 3 lines that matter are buried in noise

“99% of the log is info / debug chatter — the errors that actually explain the outage are lost in it.”

How Log Parser solves it
  • Auto-classifies each line error warn info debug from RDK <E>/<W> markers & keywords
  • A severity bar shows live counts; filter to “warnings & above” in one click

💾 An hour of analysis, gone when the tab closes

“I narrow a bug down, then lose it all on refresh — or I find the smoking gun and can't get back to it tomorrow.”

How Log Parser solves it
  • Save a parsed set as a named workspace and reload it any time
  • Pin the smoking-gun lines with a star and attach a multi-line note — jot down as much context as you need right on the line (Enter for new lines, Ctrl/⌘+Enter to save)
  • Go to line jumps straight back to any pinned line — saved per user across logins

🤝 Handing off a finding means re-doing the work

“Telling a teammate ‘look at 11:14:07 in wifimon’ over chat never lands — and to see it for themselves they have to redo the whole upload and extraction from scratch.”

How Log Parser solves it
  • Share a saved workspace with specific teammates — pick them by name from your user list — and they reopen the identical parsed logs in one click, nothing to re-upload or re-extract
  • Recipients get a “Shared with you” list on their home page — the workspace is just there, ready to load
  • Notes stay collaborative: they see your pinned lines & notes right on the timeline and can add their own, so the investigation moves forward together instead of as a one-way hand-off

🔐 Everyone's own script, on wide-open logs

“We each keep a half-broken parsing script, and device logs really shouldn't be sitting around unprotected.”

How Log Parser solves it
  • One shared, self-contained app on the LAN — nothing to install per person
  • Access limited to authorized users: hashed passwords, login throttling, hardened sessions
  • Each person's workspaces & notes stay private by default — shared only with the teammates you choose — with a storage quota

🗂 600+ files, and you need six

“The dump has hundreds of logs and I only care about the Wi-Fi ones — picking them out by hand is a slog.”

How Log Parser solves it
  • A searchable multi-select that scales to hundreds of sources
  • A one-click Wi-Fi Analysis preset pulls just the relevant logs
  • Toggle any source in or out instantly from the legend
